# Trajectory Bank v1

The driver and CLI archive task episodes from displaced conversation in
the nearest `.quasipilot/.trajectorybank` during session compaction. Search starts
at cwd, then walks its parents; a nearer workspace wins. If none exists, use
`cwd/.quasipilot`. The home configuration directory is not treated as an ancestor
workspace (unless launched from home itself). CLI workspace references use the
same resolution. Working-directory semantics for tools and AGENTS.md are unchanged.
When enabled, CLI startup creates or reopens the Chroma database and collection
in that workspace, even before a session starts. Existing records are preserved;
initialization errors fail startup rather than silently disabling the bank.
No server or startup model download. Disabled startup leaves Chroma untouched.
Direct library usage remains lazy unless `TrajectoryBank.initialize()` is called.

## Configuration

Workspace `.quasipilot/config.toml`, read at CLI startup and when building the agent:

```toml
[trajectory_bank]
enabled = false
automatic_min_similarity = 0.72
search_min_similarity = 0.35
automatic_results = 2
search_results = 5
automatic_tokens = 1200
search_tokens = 3000
```

The middleware is disabled by default. New CLI workspaces receive these defaults automatically. Startup also appends
the section to existing files when absent, preserving existing values and comments.
Missing keys within an existing section use defaults without rewriting it. To migrate from
`.quasipilot/.trajectorybank/config.toml`, move its keys into `[trajectory_bank]`
and remove only the old config file. A remaining legacy file raises a migration
error; no fallback or merging is performed. Database files remain untouched.

Set `enabled = true` and restart to enable offloading and recall. Explicit existing
settings are preserved. Disabled startup does not construct a bank or embedding model.
Set `enabled = false` and restart the CLI to disable recall middleware, its tool
and prompt, and new archival. Session compaction still uses the same cumulative
prose-arc pipeline; prior memory, archive files, and published references remain available. Re-enabling makes
that evidence available again. Programmatic callers can override the workspace
setting with `DriverAgentConfig(..., trajectory_bank_enabled=False)` (or `True`).
A caller-supplied coordinator must also have archival disabled; inconsistent
configuration is rejected rather than silently mutating the caller's coordinator.

Scores are cosine similarities, **not confidence probabilities**. These are
conservative starting points for the pinned embedding identity, not universal
cutoffs. Automatic recall may return nothing; it never falls back to weaker
matches. Explicit search trades precision for recall. Exact references bypass
similarity thresholds, but not provenance validation or output budgets.

## Compaction and Records

`TrajectoryBankMiddleware` implements the optional
[session-compaction evidence interface](../../compaction/README.md). The same
middleware instance handles archive validation/preparation/persistence and agent
recall. Only enabled driver/CLI assembly installs it. `Compactor` owns all model
calls and has no import or dependency on the bank implementation.

One extraction call groups newly evicted work into rich task episodes. A second
call writes a cumulative session arc using those episodes, the original evidence,
and previous memory. Both use the existing compactor model. Review also sees all
three sources, so extraction mistakes need not propagate into the session arc.
There is no JSON schema, task-ID generation, or exact turn-assignment gate.
The prompts preserve concrete findings, mechanisms, constraints, verification,
failed approaches, reusable discoveries, source turns, and retrieval keywords.
Recency prioritizes detail without erasing older durable knowledge.

The existing `max_critic_loops` bounds content-focused review/revision (default one).
On exhaustion, log a warning and use the latest nonempty draft. An empty initial
extraction or initial arc fails without publication; an empty revision keeps the preceding draft.
Preservation of prose facts is model-dependent, not a deterministic merge guarantee.

Each extracted task episode becomes one new document. Markdown `##` task headings
are soft record boundaries (headings inside code fences are ignored); unstructured
output stays intact as one document rather than failing validation. No semantic
coverage guarantee is inferred from formatting. Each eviction batch receives a stable
`batch-...` group in the existing `arc_id` metadata field. Episodes remain grouped
by batch; historical task-group references remain valid.
The session-arc model receives each episode paired with its exact record reference.
The harness appends all published group references and the raw-session path even
if the model omits citations, and carries the manifest through subsequent compactions:

```text
trajectory://<session-id>/<arc-id>
trajectory-record://<record-id>
```

Only turns selected for eviction are archived: the newest `keep_last_turns` turns
remain in context and are not offloaded. Zero retains none; a count at least as
large as the available turn count archives nothing. The cutoff counts turns,
not their numeric IDs. The retained tail is read-only orientation for arc synthesis.

Episodes connect user intent and corrections, execution findings, and assistant
outcomes in standalone prose, rather than embedding concatenated turn logs. The
prompt asks for files, symbols, keywords, causal discoveries, verification limits,
and task-specific turn citations. Raw tool output is available to extraction but
is not mechanically appended to documents. Even a turn without reasoning can
contribute meaningful context. Previous memory provides continuity only; it is
not archived anew. Extraction never receives the retained tail.

New archives are immutable episodes of progress, not rewritten lifetime tasks.
Later episodes can cite earlier ones. Existing records are not migrated or
re-embedded, and no duplicate per-turn records are created for new evictions.
The session arc is the working map, episodes provide deeper task accounts, and
raw sessions retain original evidence. Episode fidelity is model-dependent;
the bounded reviewer revises the session arc, not the archived episodes.

Metadata keeps schema version 1, session/arc, timestamps, source event IDs/path/
fingerprint, content hash, and extracted keyword metadata. New records use
`source_kind = "task_episode"`, `episode_index`, and `source_turns` (JSON list).
Provenance conservatively covers the entire newly evicted batch, not a guessed
per-task partition; task-specific citations stay in prose. `turn` remains the
batch's first turn for backward-compatible ordering. Timestamps describe that
batch, not the precise lifespan of each task. Keyword metadata is derived from
document terms; the model's richer Keywords line is embedded with the prose.
There is no separate keyword-search engine. Identical source/content retries are
idempotent. Original raw events are not rewritten by the bank.

Archives are persisted and checked before a session rewrite is returned. The
curated `trajectory_manifest` is the publication authority: unpublished records
from failed/stale compactions cannot be recalled. Snapshot checks reject a
rewrite if its source window changed, including overlapping trajectory compaction.
Latest SYSTEM.md/AGENTS.md entries remain pinned by existing session mechanics.
Legacy session memories enter synthesis as source text without fabricated bank references.

## Retrieval

- After a successful `reasoning` call, its text deterministically queries the
  current session. Eligible evidence is appended to that tool result, not a new
  user/system instruction. Automatic recall failures do not abort the run.
- `trajectory_bank(query="whitespace edit diagnostics")` performs deliberate
  search. `scope="workspace"` includes other sessions archived in this workspace.
- `trajectory_bank(ref="trajectory://session/arc")` loads an arc's records in
  turn order. Arc `offset` is a record index; record-ref `offset` is a character
  position. Truncated output provides a continuation offset.
- Reasoning/retrieval batches defer other tools with a tool-error result; the
  agent must inspect evidence before reissuing actions in the next model step.
- Record IDs in active tool messages suppress repeat automatic recall. Once
  compaction removes that evidence, it becomes eligible again. Explicit reference
  requests always allow pagination/re-reading.

Recalled text is enclosed in `<trajectory_evidence>` with one `<record>` per
document and a short notice that historical evidence is not current instructions.
Delimiters remain closed after truncation; embedded markup is escaped. This is
rendering-only: stored documents, embeddings, and character offsets are unchanged.
The wrapper counts toward the existing output budget, not the system prompt.

Search examines up to 40 candidates and applies scope, threshold, publication,
source-integrity, deduplication, result-count, and token limits. Raw evidence is
checked by event ID and fingerprint, so deletion, `/pop`, or reused turn numbers
cannot silently restore stale evidence. Exact stale references fail explicitly.
Missing session files make their records ineligible. No garbage collection runs
automatically; unpublished/stale records may remain on disk.

## Embeddings and Validation

The default is CPU-only Chroma ONNX `all-MiniLM-L6-v2`; first embedding use downloads its model
to Chroma's user cache. Embedding text stays local; synthesis/review still use
the configured compaction LLM. Long inputs are embedded
in 220-token windows, mean-pooled and normalized rather than silently truncated.
Collection metadata pins the model/pooling identity and rejects incompatible
reopening. Changing embeddings requires an explicit migration/reindex, not merely
changing a threshold. A missing model/network or archive error leaves the session
uncompacted. Exact retrieval does not require the embedding model.

### Override the Embedding Model

`core/trajectory_bank/defaults.py` owns `get_default_embedding_model() -> Embeddings`
and `DEFAULT_EMBEDDING_IDENTITY`, following the LLM default-factory convention.
The CLI, driver, and retrieval eval all use it. To change the default, return your
provider's LangChain `Embeddings` instance and update the compatibility identity
in that same file. Install the provider's integration package if needed; the
factory loads cwd `.env` like the LLM factories. Keep construction lazy if the
provider otherwise downloads weights or performs network calls during startup.

The bank calls `embed_documents()` for archival and `embed_query()` for search,
preserving provider-specific document/query behavior. No provider needs a custom
harness attribute or callable interface. A caller can also inject an existing
LangChain model directly:

```python
bank = TrajectoryBank(
    cwd,
    embedder=embedding_model,  # Any langchain_core.embeddings.Embeddings instance.
    embedding_identity="provider:model:revision:dimensions:prompts:v1",
)
```

Custom models require an explicit, nonempty identity. Include settings that
affect vector compatibility: model revision, dimensions, prompts, and pooling.
Changing them requires reindexing existing evidence and recalibrating thresholds;
there is no automatic reindex command in v1. Hosted overrides send embedding
text to that provider and may incur charges. The unchanged MiniLM default keeps
the prior identity and remains compatible with existing banks.

See the [LangChain embedding interface](https://docs.langchain.com/oss/python/integrations/embeddings/index#interface).

### Evaluation

```sh
conda activate quasipilot-harness
python -m pytest tests/test_trajectory_bank.py
python evals/trajectory_bank_retrieval.py
```

The initial synthetic 16-case smoke set recalled 5/10 relevant queries
automatically with zero false automatic recalls; explicit search found all ten.
This is a small sanity check, not a production precision guarantee. Evaluate
real reasoning/trajectory pairs before lowering the automatic threshold.
Retrieval telemetry records scores, selected IDs, threshold, scope, output
tokens, stale counts, and errors. Arc detail quality remains model-dependent;
coverage validation cannot prove semantic completeness. Evidence manifests grow
with compactions; hierarchical arc retirement is intentionally outside v1.
